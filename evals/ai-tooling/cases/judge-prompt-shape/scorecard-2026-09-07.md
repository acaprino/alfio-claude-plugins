## Observations

All six MUST assertions pass and both SHOULDs pass. The traps the scoring notes warn about were both hit rather than dodged.

Assertion 3's trap (a 1-10 scale kept as a preserved interface with the cost unnamed) does not occur: no variant keeps 1-10, the surviving scalar is B's 0-5, the scale change is reported as an interface break that invalidates history ("no arithmetic mapping makes it transfer, because the new scores are not a rescaling of the old blend"), and the pooled-default reversal is named on the right side of the argument, as the weakest link in the case for 0-5 rather than as support for it.

Assertion 5's trap (deleting "be very strict" without understanding it) also does not occur: the line is priced against a named benchmark and the removal is accompanied by a prediction of the direction scores will move and a warning that this reads as regression but is recalibration.

Two things I checked adversarially and let stand. First, assertion 2's "says why": the reason is stated in B's row and B's give-ups rather than inside A's own paragraph, but it is stated in the comparison that decides between them ("six criteria in one context still share one bias and one reading of the candidate"), which is where the decomposition argument actually lands. Second, assertion 8 is a negative assertion, which can pass vacuously if the run never considered multi-judge schemes at all; here it did consider aggregation and explicitly declined to recommend it for this target, so the path was exercised.

The one soft spot is assertion 6's final clause. Per-criterion Cohen's kappa on the caller's own labels is unambiguously present and unambiguously framed as the number that decides usability, but the word "first" is spent elsewhere in the delivery on the parse-failure rate. I scored it pass because both substantive halves are met and the kappa bullet is the one the delivery calls decisive, but a reader scoring the clause literally could mark it fail.

Two smaller notes with no scoring effect. The run declines to pick a variant and hands the frontier choice to the user, which the case does not assert either way. And the run marks two scorecard dimensions N/A with reasons, one of which ("a judge wants none: variation in a score is noise, not latitude") is judge-specific reasoning that corroborates assertion 1 beyond the archetype label itself.

I did not read anything under plugins/, docs/, or .peer-review/; all evidence above is quoted from the run output and the case file.

## Assertion quality

Assertion 6 is the one I would flag. Its first two clauses ("stated as predicted until Cohen's kappa is measured on the caller's own labels" and "one kappa per criterion") are crisp invariants and were checkable verbatim. The third, "the delivery names that as the first number to collect," is ambiguous in a way that bit here: the output names a different metric as the thing to collect first for a different dimension (parse-failure rate, for schema compliance), while naming kappa as the number that decides whether the judge is usable. Two careful readers would split on whether "first" means ordinally first in the delivery or first among agreement numbers. Suggest tightening to "the delivery names per-criterion kappa on the caller's own labels as the measurement that decides whether the judge is usable," which tests the same thing without depending on bullet ordering.

Assertion 4's second clause ("removing it is reported as a relaxation") is structurally unfalsifiable whenever the first clause passes: if the placeholder survives in every variant, nothing was removed, so the clause can never fire. It is harmless as written but adds no discrimination; it would only earn its place if the case expected a variant that drops the reference. Same structure in assertion 5's "if a variant keeps it" clause, though that one is a genuine escape hatch for a defensible alternative shape rather than dead text.

Assertion 8 is a negative assertion and therefore carries the usual vacuity risk: a thin response that never discusses judge ensembles at all would pass it for the wrong reason. It happened to be genuinely exercised in this run. If the harness keeps it, consider pairing it with a positive form (the response prices multi-judge schemes and declines them for this target) so it cannot pass by silence.

Assertions 1, 2, 3, 5 and 7 are well-formed invariants: each names an observable feature of the output, none encodes a wording preference, and 3 in particular is written so that both defensible outcomes (move to 0-5, or keep 1-10 flagged as a caller decision) pass, which is the right shape.
